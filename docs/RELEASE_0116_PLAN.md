# Version 0.1.16 release plan

October 2, 2026. Owner requested the next installed version with all accumulated features and a comprehensive security/compliance inventory, and confirmed tray closure. Audience remains one Ontario owner. This plan precedes the metadata change and packaging.

## Scope and exact release gates

1. Inventory current renderer, shared models, services and outstanding compliance evidence. Publish [the capabilities inventory](APP_CAPABILITIES_0116.md) with separate shipped controls, experimental controls and uncompleted organizational assurance. Preserve PHIPA exclusion. Do not assign certification, legal compliance, percentages or maturity levels without evidence.
2. Create fresh ignored 0.1.16 helpers and evidence paths. Change only package version and the two root package-lock version fields from 0.1.15 to 0.1.16; preserve dependency resolutions. Keep previous release artifacts and evidence intact.
3. Independently check ordinary owner processes are closed. Resolve the physical normal configuration and profile, reject links/redirection, check every account SQLite database, and make a new byte-verified private backup. Never print record contents, credentials, account identifiers or startup commands into public documentation. If closure/physical identity fails, do not install.
4. Run credential scan, tooling tests, type checking, unit/UI tests, build, dependency audit/SBOM and cloud-rule emulator tests. Require zero skips in the full Windows CI acceptance run and zero npm vulnerability findings. Local symlink tests must explicitly disclose missing privilege; their successful CI counterparts are required rather than treating a local skip as a pass. Do not deploy provider policy, rules, IAM, logging, protection or billing as part of this release.
5. Build the Windows x64 installer from the final versioned source. Check package boundaries, native inventory, Chromium notices, ten bundled/copied JavaScript/Node license notices and 23 unchanged MPL source files. Do not use test-modified executables as the shipping artifact.
6. Run all original desktop tests, independent renderer tests and all-seven-fuse compatibility tests on disposable copies. Verify fresh/restart email/Google/reset availability with configured and missing configuration. Original shipping fuse settings remain unchanged; compatibility success is not production hardening or native acceptance.
7. Test a populated synthetic upgrade from actual 0.1.15 installed bytes to 0.1.16: records, recurrence exceptions/completions, links, preferences, device state and outbox. Require preservation and ordinary exits. Before retaining/installing, recheck final package hashes and earlier retained installer hash.
8. Retain a new local installer without overwriting any earlier release. Generate the install helper with the exact tested installer/archive fingerprints. Immediately before installation, require app closure and equality with the verified profile backup. Install silently in the ordinary desktop context, checking physical installed version, archive, notices and unchanged Windows startup registration/approval.
9. Before opening the owner profile, compare every account's records and every non-cache profile file with the backup. Verify installed application/notice/source bytes against the tested package. Preserve the backup; local backups and SQLite files are not encrypted by the app.
10. Run the physical normal-context installed sign-in gate through fresh start and ordinary restart using an isolated profile and a private configuration copy, then remove that copy. Require enabled email/Google/reset controls and unchanged owner configuration. Also verify actual live email/password sign-in, Windows-encrypted remembered session, restart and sign-out using only a disposable identity, then independently verify cleanup. Do not change owner credentials or infer Google consent/email delivery from enabled controls.
11. Verify read-only Windows startup state and reopen the normal installed launcher without debug/test-profile arguments. Record whether the owner account is restored separately from fresh Google browser consent. Actual physical logon/sleep/unlock/banner click/native dialogs and another PC remain explicit acceptance gates.
12. Commit/push the release source and inventory to the existing draft PR; verify Windows CI and retained evidence. Update release notes, installation/sign-in evidence and current checklist with measured results. Report the installed version, available local installer, features, security controls, compliance status and precise remaining dependencies.

## Recovery and stop rules

On any failed build/test or mismatched hash, repair and rerun affected gates before installation. On profile/process mismatch, preserve the owner profile and installer and wait for safe closure; do not terminate the owner app or restore over current data. On a live fixture failure, clean up the exact owned identity/configuration and retain sanitized failure evidence. A failed test stays recorded even after a successful retest. No new public release, main merge, signing purchase or assurance claim is authorized by this owner-only update.

## Completion evidence

Installed 0.1.16 must be distinguished from source-only and disposable hardened copies. [Implementation status](IMPLEMENTATION_STATUS.md) will retain actual test counts, artifact identities, backup/preservation results, cleanup and limits. [Compliance checklist](COMPLIANCE_CHECKLIST.md) retains unmet gates; shipping an update does not close them.
