# Course filters, editing and dialog pointer behavior

September 30, 2026. Three reported issues: Windows native dropdown options inherit pale themed text on a white popup; course editing is not discoverable from the calendar; a selection drag ending on the backdrop dismisses the course form. Implement as a separately retained 0.1.14, preserving installed 0.1.13 and its verified private backup/artifact.

1. Inspect the native course/type/task selectors, existing course editor entry points and the shared dialog dismissal handler before changes. Existing course cards already edit their stored course; expose this capability clearly instead of creating another editing model.
2. Use black text on white for native select options/option groups, independent of the selected app palette. Keep the closed select readable on its themed background. Test computed option foreground/background in all three presets and a saved custom scheme; observe normal option selection/filtering. Native OS popup painting remains an owner observation if unavailable to browser automation.
3. Add an accessible, visible Edit course button beside each active sidebar course, retaining the adjacent filtering button and its selected state. Use sibling buttons, never nested controls. Add explicit edit wording to the existing course card. Both entry points must open the same editor for the same stored ID; save edits updates labels/filter options and linked item presentation, without duplicating or reassigning calendar items. Long labels must not push edit controls out of the sidebar. Archived courses remain editable in Courses & semesters with Include archived.
4. Make shared backdrop dismissal require a primary-button gesture beginning outside the dialog and ending outside it. A drag beginning in an input/content area and ending on the backdrop must preserve the open form and draft. Pointer cancellation clears pending dismissal. Real backdrop clicks, close button, Cancel and Escape retain behavior. Do not disable the browser's text selection or add global document listeners.
5. Add independent renderer acceptance using a synthetic profile and Node CLI inspection disabled. Exercise real mouse selection/drag release outside the form, retained draft, true backdrop dismissal, Escape and close controls. Measure viewport geometry rather than relying on runner display size; keep the sidebar navigation reachable.
6. Add native option style/preset selection acceptance with UI filtering and synthetic screenshots. Check automated A/AA accessibility after adding controls. Run source/secret/tooling/type/unit checks, cloud regression, final packaged desktop and independent tests, package/native/notices/exact-dist checks and dependency gate. Original desktop tests remain until independently equivalent coverage passes.
7. Retain exact 0.1.14 installer/archive identities, push source/tests and require fresh Windows CI. Carry forward the completed 0.1.13 installation and corrected CI evidence distinctly; do not replace existing retained artifacts or make a public release/certification claim.
8. Install only after a new tray-closure confirmation and a fresh normal-context verified profile backup. Verify all-account/non-cache preservation, actual installation bytes/notices, unchanged Windows startup command/approval and private configuration readiness before normal reopen. Continue the existing SOC 2/ISO 27001/CAN-DGSI 118/PIPEDA work; PHIPA remains withdrawn.
