7. Re-run the populated fixture against installed 0.1.8. Run all 26 desktop tests against that installed executable using isolated test profiles. Retain versioned results. Repeat ordinary launches and verify shortcut stability. Automated notification cases do not establish that a new Windows banner was visibly delivered or clicked.
8. Update the installed-version evidence and remaining-risk documents, preserving dated historical checkpoints. Keep raw profile copies, credentials, synthetic data and installers ignored. Leave the verified current app available to the owner. Continue the next independent release/compliance preparation task only after this upgrade passes.

## Recovery and scope

If installer execution or a preservation check fails, retain the before-profile copy and exact 0.1.5 installer, record the failing gate, and diagnose before attempting recovery. Reinstallation or profile restoration must preserve newly written data and cannot be inferred safe from a version label. Existing provider sessions may refresh while the app opens; do not print or compare decrypted credentials. The populated fixture establishes migration behavior even if the active real profile has no calendar records. Clean-PC, another physical device, sleep/login, live inbox delivery, native banner observation, signing, operator-approved security/privacy controls and independent assessment remain separate acceptance items.
