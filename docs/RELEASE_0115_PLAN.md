## NODE_OPTIONS probe refinement before implementation

Electron's [environment-variable documentation](https://www.electronjs.org/docs/latest/api/environment-variables#node_options) states that packaged GUI apps disallow most NODE_OPTIONS, including a preload. An absent GUI preload would therefore not isolate the nodeOptions fuse. Use an owned Node-mode harness with runAsNode left enabled in both copies: an enabled nodeOptions control must execute the synthetic preload; a copy differing only in nodeOptions must execute the ordinary harness, ignore the preload and retain the default HTTP-header limit. Both Node-mode processes must exit zero. Separately start and close both calendars normally through the existing independent transport. Do not represent this as a preload attack working in a packaged GUI or as runAsNode protection. Other fuse probes and production integration remain open.
