## Scope and invariants

Use the pinned Electron 44.4.5 Windows x64 binary and its [versioned fuse schema](https://github.com/electron/electron/blob/v44.4.5/build/fuses/fuses.json5). Preserve the owner profile, retained installers, private configuration exclusion, notification identities, SQLite schema and cloud protocol. All experiments use disposable copies beneath ignored `test-results`, with explicit synthetic profiles. Never flip bytes in an installed executable, overwrite a retained release, or enable a debugging exception in a shipped artifact to make tests pass.

| Fuse | Required final state | Compatibility evidence |
| --- | --- | --- |
| runAsNode | Disabled | Synthetic `ELECTRON_RUN_AS_NODE` invocation cannot execute a sentinel script; ICS worker/import and normal startup pass. |
| cookieEncryption | Enabled | Clean-profile and existing-profile startup work; authentication/session preservation remains separately verified through Windows secure storage. |
| nodeOptions | Disabled | Synthetic `NODE_OPTIONS` preload cannot create its marker; ordinary launch succeeds. |
| nodeCliInspect | Disabled | Node inspector does not listen with inspect arguments; acceptance of the final artifact does not depend on main-process inspection. |
| embeddedAsarIntegrityValidation | Enabled | Unique embedded header digest matches the actual archive, untouched copy starts, altered header and altered loaded-file bytes fail closed. |
| onlyLoadAppFromAsar | Enabled | Removing the archive cannot fall back to a synthetic `resources/app` or default archive. |
| grantFileProtocolExtraPrivileges | Disabled | Custom `cclime` calendar, assets, 404 and sender/origin boundaries work without privileged file pages. |

Leave browser-specific V8 snapshot and WASM trap settings unchanged until there is a separate reason and test plan. [Electron's fuse guidance](https://www.electronjs.org/docs/latest/tutorial/fuses) and [ASAR integrity instructions](https://www.electronjs.org/docs/latest/tutorial/asar-integrity) define the mechanism; static matching does not establish runtime enforcement, publisher identity or comprehensive tamper resistance.

## Ordered implementation and fail conditions

1. **Static integrity prerequisite.** Inspect the final executable's PE resources without executing or editing it. Require exactly one `INTEGRITY/ELECTRONASAR` resource and exactly one expected `resources\\app.asar` entry, SHA-256 and a valid digest. Compare against the archive's actual raw header string. Reject absent, ambiguous, malformed, unsupported or mismatched evidence. Tests must include a real synthetic PE resource and archive, plus header mutation and ambiguous entries. Report separately whether the two enforcement fuses are enabled; matching metadata must never be reported as active protection.
2. **Independent acceptance feasibility.** Start a disposable package copy with CLI inspection disabled, outside `electron.launch`. First evaluate whether Chromium's existing loopback-only remote-debugging transport can drive renderer interactions without a new application hook, altered preload, enabled Node inspector or changed DevTools preference. Use a random port, explicit synthetic profile and owned process handle; close only that process. If unavailable, design external Windows accessibility automation. An unavailable transport leaves this gate open; it must not justify keeping inspection enabled in production.
3. **Coverage migration.** Classify each existing desktop assertion by renderer, main-process, OS or storage observation. Keep equivalent meaningful coverage: startup/version, create/edit/delete/undo, recurrence overrides/completions, seven-day tasks, keyboard/accessibility/zoom, worker import, 404/sender denial, backup/restore/restart, queued changes and close-to-tray/second-launch behavior. Replace direct main-process stubs with real external observations or fixture preparation wherever possible. State explicitly which observations need manual Windows acceptance.
4. **Negative probes.** Demonstrate each probe against an unhardened disposable control where applicable before relying on absence of a sentinel. Distinguish expected integrity termination from missing dependencies, launch failure, modal crash UI or timeout. Collect bounded exit status and sanitized diagnostics. Do not count a timeout or forced cleanup as a passing refusal. Never pass account credentials to a probe.
5. **Build integration.** Only after the transport and coverage gates are viable, create a new artifact version. Configure reviewed fuse changes during packaging before signing/installer creation, using supported tooling and pinned inputs. Re-read the final executable, embedded resource and final archive after all mutations; require all seven target values and exact metadata equality. Retain the unchanged 0.1.9 baseline. Run dependency/signature/credential checks for any new tooling.
6. **Tampered copies.** Preserve a verified original and hashes. Mutate only fresh disposable package copies: raw ASAR header, content of a file actually read at startup, and missing archive with an alternate app marker. Require the original to launch first and each tampered copy to refuse application execution. Explain that unpacked native modules, a replaceable unsigned executable and local administrator compromise remain outside this check.
7. **Final acceptance.** Run unit/tooling/cloud/build/package checks and migrated production desktop acceptance on the exact hardened bytes. Verify worker imports, Google loopback mechanics, encrypted sessions, tray/startup/notification identity and logical recovery. Re-run populated fixture preservation and the installed upgrade only after normal owner closure. Fresh banner/click, sleep/login and clean-PC behavior need their own observed results.
8. **Evidence and continuation.** CI must exercise the hardening and negative gates and retain versioned sanitized evidence. Update risks and the draft PR only with observed results. Do not remove legacy coverage before equivalent checks pass. Signing, broader native provenance, complete notices, remote abuse controls and organizational/independent assurance remain separate work.
