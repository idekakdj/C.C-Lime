# Completed tasks, weekly progress and to-do ranges

October 1, 2026. Source-only continuation at unchanged 0.1.14; no installation/replacement release/live rule deployment. Prior calendar/repetition checkpoint remains separately verified at `9d662df`.

## Observed causes

The task page shares the calendar predicate, including Hide completed. Completed tasks therefore disappear even with the Completed tab selected. Its inventory also uses only overdue open tasks plus dated tasks from 30 days ago to 181 days ahead, dropping older completed records. Weekly progress counts dates from today to seven days ahead rather than the week defined by the user's first-day preference; undated tasks and overdue tasks finished this week are omitted. These are presentation/inventory defects, not evidence that the completion command failed to store a status.

## Ordered implementation and gates

1. Add independent actual-desktop regression tests that reproduce hidden/older completions. Save synthetic old/undated/repeating tasks, complete through visible buttons and compare persisted status/state with Completed list and weekly progress. Keep owner data untouched and summaries dependent on normal exit.
2. Build a task-only inventory: all saved non-repeating dated tasks across supported dates; recurring near-window occurrences; all overdue recurring occurrences; and explicitly recorded occurrence states/overrides outside the window. Exclude unrelated classes/events and deduplicate occurrence keys. Expand historical recorded occurrences in short display windows; preserve cancellation rules and count bounds. Keep the existing worker acknowledgment/invalidation protocol.
3. Separate task status/range predicates from calendar Hide completed and calendar type/course selectors. Default to All to preserve the existing to-do section. Add an accessible Task range selector with Current week, Current month and All. Week honors the saved Monday/Sunday start and displayed zone; month uses the current month rather than the viewed month. Undated to-dos remain available in every range. Completed ranges include a due date in the range or a completion timestamp in the range.
4. Infinite recurring schedules require a bounded forward horizon. All includes all saved standalone dates and saved occurrence history plus repeating to-dos for the next six months and overdue repeats. Disclose this in the task UI so All does not imply expansion of an infinite series. Retain 50-row paging and all existing progress tabs.
5. Weekly progress includes tasks due during the current calendar week, open undated to-dos and tasks finished during that week (including old/future deadlines and undated tasks). Historical completed undated tasks are not counted forever. Deduplicate identities, count completion per occurrence, and make the bar an accessible progressbar with numeric/text values. Calendar Hide completed/range changes cannot alter the count. Undo/reopen updates it immediately; restart re-derives it from stored status and completion timestamps. Removed tasks remain governed by existing lifetime-history behavior.
6. Pure tests cover earlier-week completions, overdue/undated work completed now, Monday/Sunday boundaries, displayed-zone timestamps, old/far-future standalone dates, historical recurring state/override/cancellation and unrelated-class budgets. Independent UI tests cover completion, Completed visibility despite Hide completed, progress/undo/restart and every range with a far-future record.
7. Run the affected unit/type/worker/UI tests, full unit/cloud and independent/original desktop suites after final changes. Recheck credential/package/archive/native/dependency gates. Record exact source/package digests and fresh Windows CI. Extend the acceptance register by measured assertions only; native dialogs, remaining fuse probes and organizational assurance remain open. Do not bump version, install or deploy live cloud rules.
